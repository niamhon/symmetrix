# Native Symmetrix LSC in ASE

Use the development installation for this new interface until a separate
validated release is promoted. The stable installation is unchanged. The
original PyTorch calculator remains the independent correctness/benchmark
reference; no native MACE-SCF source or frozen references are replaced.

## Export and evaluate

Use the existing `symmetrix_extract_mace`/`python -m symmetrix.cli.extract_mace`
exporter for a supported LocalSplitCharges checkpoint. Load its JSON, not the
PyTorch `.model`, in the Symmetrix calculator. Runtime inference does not import
PyTorch or start LAMMPS. Exporting still uses the original model dependencies.

```python
from symmetrix.experimental import MACELSC

atoms.calc = MACELSC(
    "model.symmetrix.json", device="cuda", dtype="float32-mixed",
    electrostatics="auto", mesh_spacing=0.7, mesh_order=8,
)
energy = atoms.get_potential_energy()      # eV
forces = atoms.get_forces()                # eV/Å
stress = atoms.get_stress()                # eV/Å³; periodic systems only
charges = atoms.get_charges()              # e
dipole = atoms.get_dipole_moment()          # eÅ
energies = atoms.get_potential_energies()   # eV, includes electrostatics
```

CPU uses `device="cpu", dtype="float64"`. GPU defaults to `float32` and also
supports `float32-mixed`; physical electrostatics/reductions retain FP64. Solver
and hardware options are read-only after construction: create a new calculator
to change them. The model is loaded once per calculator.

`auto` selects native mesh for full 3D periodicity and direct finite-cluster
electrostatics when all PBC flags are false. Mesh spacing/order are validated
starting settings, not a universal accuracy guarantee. `direct` also allows
native reciprocal-space checks of periodic cells. Explicit `mesh` rejects
clusters. Slabs/partial periodicity are unsupported. Clusters may have no cell;
requesting their stress raises `PropertyNotImplementedError`.

ASE caches energy, forces and periodic stress from the same evaluation. Charges,
dipole and per-atom energies are read only when requested, without rerunning the
model for an unchanged configuration. Per-atom energies use the LAMMPS
partition, including electrostatics and external-field terms; this partition is
not a unique atomic observable. Their sum reproduces the total energy.

The compiled C++ neighbor builder returns indices and image shifts; geometry is
refreshed on each new evaluation. The GPU uses the existing batched local/source
reverse, batched source forward and compact first-layer paths where supported.
There is no persistent neighbor-list skin/cache in this first version.

## Fields, charges and dipoles

The optional constructor `external_field=(Ex,Ey,Ez)` overrides
`atoms.info['external_field']`. If it is `None`, the info value is used, with
zero as the default. Units are eV/(e Å), with the existing `+E·dipole` energy
convention. Changing the effective field invalidates ASE's cache, including
in-place edits to an info array. `calc.external_field` can be changed or reset
to `None`; other solver/hardware settings require a new calculator.

LSC predicts charges using its exported species/formal-charge architecture.
There are no Polar-style adjustable total-charge/spin arguments. Initial ASE
charges do not replace the model's charge prediction. Keep identical coordinates
and polarization branches when comparing total dipoles; this wrapper does not
silently wrap or translate atoms.

## Independent reference and tests

Continue using unchanged
`mace_scf.calculators.localsources.MACELocalSplitCharges` from the pinned
`mace-scf-dev-niamh` checkout for FP64 uncompiled reference evaluation. Save
native predictions before comparison. Dataset labels are not the inference
implementation oracle. The old `LSCCalculator` remains unchanged for compatibility
and old/new wrapper benchmarks.

The new tests are `symmetrix/test/lsc/test_ase_fast.py` and opt-in
`test_ase_fast_organic.py` (`LSC_RUN_ORGANIC=1`). CPU can be selected with
`-m 'not lsc_cuda'`; CUDA checks require an allocated GPU and can be selected
with `-m lsc_cuda`. Frozen references are never regenerated by pytest.

Gates remain energy 1e-6 eV/atom; forces atol 8e-5 eV/Å, rtol 1e-4; stress atol
5e-7 eV/Å³, rtol 1e-4; charges atol 2e-6 e, rtol 1e-5; dipole absolute 3e-5 eÅ.
Per-atom energy sums are checked at 1e-8 eV/atom. Tests cover native parity,
periodic images, cell-less clusters, solver switching, cache/field invalidation,
optional outputs, dispatch counters and ten-step ASE dynamics.

The fixed absolute total-dipole gate is not guaranteed at arbitrary system
size in FP32. A perturbed 10,368-atom water frame gave 3.57e-5 eÅ error in
the new FP32 ASE path and 4.52e-5 eÅ in the unchanged LAMMPS FP32 path, against
the retained 3e-5 eÅ gate. CPU FP64 Symmetrix was within 3.2e-10 eÅ. This is
a shared precision limit; the failed gate is recorded, not relaxed. Validate
the intended system size and observables, using FP64 for stricter dipole needs.

## Timing

`tools/lsc/benchmark_ase_lsc.py` accepts `--export`, `--native-model`,
`--data-dir` and `--output`. The data directory contains existing
`water-192.data`, `water-1536.data`, and `water-10368.data` LAMMPS charge-style
files with types 1=H and 2=O. It saves new native FP64 predictions before any
Symmetrix comparison, records input/model hashes, and preserves raw timings.

Report direct and mesh separately: the native ASE reference uses direct sums,
so a native/direct-to-Symmetrix/mesh ratio includes a solver change. Old/new
wrappers are compared at matching solver and precision. All request energy,
forces and stress, include graph construction and transfers, exclude loading
and warm-up, force cache misses and synchronize CUDA. Node-only optional output
readbacks are not forced into the normal MD timing. Neighbor-building times are
reported separately. These are ASE timings, not LAMMPS timestep timings.

If full native FP64 runs out of GPU memory, preserve the failed log and report
OOM rather than a timing. For these periodically repeated neutral water boxes,
`--resume --tiled-reference --native-oom-log PATH` preserves completed sizes and
uses five fresh native 192-atom predictions, periodically repeated to the large
cell. It checks that the original box is the exact integer repeat. Large-case
perturbations then repeat the same perturbed small cell, and are saved separately
from the failed attempt's independent perturbations. This verifies translational
extensivity; it is not a full native large-cell evaluation or measured native
speed. No native-to-Symmetrix speedup is reported for an OOM native case.
